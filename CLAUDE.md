# CLAUDE.md — Agent Lore

Guidance for working in `agentlore-site/`. The monorepo root `CLAUDE.md` and `PROJECTS.md` still apply; this file covers what is specific here.

## What this site is

Three surfaces under one roof, reflected in the tagline *"Learn the agents. Pick the model. Ship the skill."*

| Section | Route | What it is |
|---|---|---|
| **The Path** | `#/learn` | Training tracks — structured reading orders through the guide corpus |
| **The Codex** | `#/codex` | Model comparison with verified prices, a cost calculator, and a routing guide |
| **The Armory** | `#/armory` | How to build agent skills grounded in sources you control |
| Browse | `#/browse` | The full corpus, filterable and shareable |
| Reader | `/t/<id>/` | **Generated static pages** — one per guide |

## Run it

```bash
make serve      # http://localhost:8818
make pages      # regenerate reader pages after any content change
```

ES modules require an HTTP server — `file://` will not work.

## Architecture

Two rendering surfaces, one renderer.

- **App shell** (`index.html` + `js/app.js`) — hash-routed SPA for browsing, the Codex and the Armory. `js/router.js` dispatches to `js/views/*.js`; every handler is delegated on `document` in `js/events.js`, so `innerHTML` swaps never orphan a listener.
- **Reader pages** (`t/<id>/index.html`) — generated by `scripts/build-pages.mjs`, committed to the repo. They are real URLs, readable without JavaScript, and carry their own light script (`js/reader.js`).

The generator **imports the site's own `renderMarkdown`** from `js/utils.js` rather than reimplementing it. That is deliberate: the two surfaces cannot drift.

> **Run `make pages` after editing anything under `js/content/`.** The reader pages, `search-index.json`, `sitemap.xml` and `llms.txt` are all generated. Forgetting means the static pages go stale against the data.

## Content model

Everything lives in `js/content/`:

```
js/content/
├── index.js          # taxonomy, aggregation, TUTORIAL_BY_ID, neighbours()
├── paths.js          # PATHS — the training tracks
├── models.js         # MODELS — the Codex, with per-row `verified` dates
├── workloads.js      # calculator presets + the cost formula
├── armory.js         # ARMORY_SECTIONS + SKILL_TEMPLATES
├── glossary.js       # GLOSSARY — feeds the command palette
└── tutorials/        # one file per category
```

**Adding a guide** = append one object to the right `tutorials/*.js` file:

```js
{
  id: 'kebab-case-slug',      // becomes /t/<id>/ — unique, never reused
  title: 'Title Case',
  description: 'One line, no trailing period',
  category: 'cost',           // must exist in CATEGORY_META
  tools: ['claude'],          // keys of TOOLS
  difficulty: 'beginner',     // beginner | intermediate | advanced
  content: `## Markdown…`,
}
```

Then add it to a track in `paths.js` and run `make pages`.

**Adding a category** = one entry in `CATEGORY_META` (`js/content/index.js`) plus a file in `tutorials/`. Its position in `CATEGORY_META` sets the corpus reading order, which drives prev/next on every reader page.

### Template-literal escaping

`content` is a template literal. Two traps:

- Backticks must be escaped: `` \` `` — including markdown code fences, which become ``\`\`\` ``
- A literal `${` must be escaped as `\${`

`node scripts/build-pages.mjs` fails loudly on a syntax error, so a mistake here surfaces immediately.

### Markdown support

`renderMarkdown` (`js/utils.js`) handles: `##`–`####` headings, fenced code with a language label and copy button, tables, nested lists, blockquotes, `---`, `**bold**`, `` `code` ``, links, and callouts:

```markdown
> [!note] Optional title
> Body text.
```

Kinds: `note` · `tip` · `warn` · `danger` · `cost`. There is no image or inline-HTML support — add it to the renderer rather than working around it.

Code-block ids are positional (`cb-1`, `cb-2`), never random, so generated pages stay byte-identical across builds. **Keep it that way** — the generator's idempotency depends on it.

## The Codex: pricing data

`js/content/models.js` publishes real prices. Rules:

- Every row carries `verified: 'YYYY-MM-DD'`. The UI computes days-since and shows an amber "may be stale" state past `STALE_AFTER_DAYS` (90).
- **Verify against the provider's own pricing page before changing a number.** Third-party summaries and blog posts get this wrong routinely; `PROVIDERS[x].source` holds the canonical URL for each.
- A scheduled change goes in `priceChange`, not by editing `price` early. `priceOn()` resolves the correct rate for a date and `pendingChange()` drives the countdown banner.
- Local models use `price: { in: 0, out: 0 }` plus `vramGb` / `hardware` / `throughput`. They sort to the bottom of any price column — `$0` is an absence of a price, not a bargain.

The calculator formula lives in `monthlyCost()` (`js/content/workloads.js`) and mirrors the worked example in Anthropic's pricing docs: cached input at the cache-read rate, the rest at base input, plus output. Cache *write* cost is deliberately excluded and the UI says so.

## Conventions

- **Links between guides use root-absolute paths**: `/t/<id>/`, never relative. Reader pages live one directory deep and relative links break there.
- **App routes are `#/…`**, reader links are real paths. The palette handles both.
- Progress is one key, `agentlore-completed`, shared by the app shell and the reader pages. Do not add a second progress store.
- Never edit `css/neorgon-header.css`, `css/neorgon-footer.css`, `js/neorgon-header.js` or `js/neorgon-footer.js` — they are vendored. Edit `packages/neorgon-ui/` and re-run the sync script.
- No file over ~500 lines except the content modules.

## Gotchas

- **Views that update on typing must patch, not re-render.** `patchBrowse()` and `patchCalculator()` exist because a full `render()` destroys the focused input and its caret. If you add a live-updating control, follow that pattern.
- The rail chip counts come from a pool filtered by *every filter except category*, so a chip reading `0` genuinely would be empty if clicked. Do not "simplify" this to a plain count.
- `search-index.json` is fetched lazily on first palette open and deliberately excludes guide bodies — it must stay small enough for a reader page to pull without thinking about it.
- `path/index.html` is a redirect stub to `#/learn` for the pre-2.0 URL. GitHub Pages has no redirect support, hence the meta-refresh.
